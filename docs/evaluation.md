运行示例：

```bash
python -m agent_learning --question "Agent Loop 为什么要有最大步数？" --max-steps 1
```

## 判定维度

逐题检查：资料是否支持回答、引用是否来自本次结果、是否正确停止，以及模型请求与实际工具执行各多少次。没有资料时诚实说明可以通过边界测试，但不是成功解答了原问题。

R05 返回退出码 1 是符合预期的结果；不能仅用所有命令是否返回 0 判断测试通过。

## 用实验检查理解

运行前预测要请求模型几次、执行工具几次；运行后逐轮指出“谁产生了这段内容，下一次模型输入增加了什么”。然后说明资料是否支持结论，以及程序为何接受或拒绝结束。

改变一个条件再运行，例如缩小请求上限或换一种问法。将结果与预测对照，尝试说明变化发生在检索、上下文、生成还是结束检查。

## 从引用结构检查到结论审阅

第 8 章的两个问题展示了不同的检查重点：

| 题目 | 程序状态 | 引用结构 | 逐条审阅 |
| --- | --- | --- | --- |
| E07：保留来源与引用的作用 | `answered` | 3 条结论，3 个引用项均合法，逐条覆盖 3/3 | 第一条“确保”需收紧为设计目标 |
| E14：RAG 服务月费 | `insufficient_evidence` | 无结论，引用指标为 `null` | 缺失说明符合资料范围，没有给出具体价格 |

引用指标取自请求中的 `evidence`，语义判断则需要逐条阅读资料。两例适合说明方法，扩大样本后才能比较整体表现。模型配置、用量、审阅方法和各次输出见 [评估报告](runs/2026-11-19/rag-evaluation.md) 与 [JSON 记录](runs/2026-11-19/rag-evaluation.json)。

## 研究报告验收清单

- **检索**：原始问题、参数、实际返回编号与入选证据可追踪。
- **数据**：来源是教学摘要还是原文，资料日期和适用范围是否清楚。
- **回答**：每条关键结论有直接支持，未把主题相关当成可回答。
- **引用**：编号来自实际发送给模型的证据，最终链接从资料记录读取。
- **缺失**：没有证据或证据不足时说明缺什么，不声称教材没有相关内容。
- **预算**：各分支的请求次数、停止条件和失败原因可追踪。
- **可复现**：保存语料指纹、分块参数、模型配置标识、代码版本与测试题；不保存密钥。

`evidence_only` 表示仅提供摘录；`answered` 表示回答通过格式和引用范围检查。两种状态都需要结合报告内容阅读。

不要把所有检查合并为一个“准确率”。检索 Recall 使用人工标注的相关文档作为分母；引用合法率使用输出引用项作为分母；问题是否回答完整、证据是否直接支持结论则需要逐题审阅。无结论或无引用时相应结构指标为 `null`，合理拒答另记为边界处理结果。拒答可以符合约束，但没有给出用户所问的事实答案。

保存问题、入选证据、原始回复、运行状态和审阅结果，便于定位问题。引用指标按已接受的结论计算时，另行统计格式拒绝和资料不足。

将回答记录交给评估入口，可以计算引用合法率与逐条结论引用覆盖率：

```bash
python -m examples.evaluate --predictions outputs/predictions.json --output outputs/full-evaluation.json
```

记录格式见 [引用评估说明](learning/evaluation.md#96-逐条检查回答)。
