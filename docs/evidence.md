## 不同验证方式分别说明什么

| 验证方式 | 验证什么 | 不能据此宣称什么 |
| --- | --- | --- |
| 固定回复的离线测试 | 请求内容、循环、预算、状态与错误出口 | 真实模型会作出同样选择 |
| 本地检索与固定题 | 给定资料及标注上的排序与召回 | 能回答整个教材或任意主题 |
| 固定输入的生成/反思演示 | 程序能组织阶段并保留反馈 | 真实模型生成质量提高 |
| 模型请求记录 | 给定输入、参数与资料下的模型输出 | 一次结果可代表总体成功率 |
| LangGraph | 库接口、节点执行、状态与路径可复现 | 框架会自动提升答案质量 |
| MCP 本地 stdio | 会话、工具发现与跨进程调用 | 获得实时互联网数据或额外模型能力 |
| 人工核对引用与答案 | 当前结论能否被给定来源支持 | 自动完成所有事实核查 |

自动检查见 [GitHub Actions](https://github.com/ldr0528/agent-learning-journey/actions)。基础环境缺少可选库时跳过相关测试，集成环境安装依赖后执行完整检查。

- 当时的文档检查覆盖 01–11 章、正文 Python 片段、相对链接、标题锚点、SVG、JSON 及关键函数与源码的一致性。
- 固定开发题的检索结果：Recall@3 为 0.9583，MRR@3 为 1.0，无答案题空结果比例为 0.5。失败案例保留在 [评估章](learning/evaluation.md)，这些指标不等于回答正确率。

## 记录格式

记录服务和模型名、问题、参数、代码提交、结束状态、请求/工具次数、引用及必要输出节选。若测量 token、延迟或费用，注明测量来源与重复次数。不得以预设演示替代实际样本，也不把改变多个条件的运行写成单变量效果。
