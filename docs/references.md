## 主教材：概念、实现与结果连在一起

[Hello-Agents 仓库](https://github.com/datawhalechina/hello-agents) 按基础、智能体构建、高级扩展与应用组织内容，并在目录中交代每章主题。本项目沿用“先理解机制，再进入框架和项目”的学习顺序，具体取舍见 [课程对应关系](course-map.md)。

重点参考 [第四章：智能体经典范式构建](https://github.com/datawhalechina/hello-agents/blob/main/docs/chapter4/第四章%20智能体经典范式构建.md)。它将流程讲解、图示、分模块代码和运行结果放在同一章内，便于读者把设计与实际行为对照。本项目对应的改编范围是：

| 教材部分 | 本项目使用方式 | 明确调整之处 |
| --- | --- | --- |
| §4.2 ReAct | 理解模型决策、程序执行与观察回传 | 用模拟天气与本地资料降低外部服务依赖 |
| §4.3 Plan-and-Solve | 先生成计划，再携带原题与历史逐步执行 | 采用 JSON 计划，增加总调用预算与状态区分 |
| §4.4 Reflection | 初稿、评审、修订和再次评审 | 将代码优化改为文字解释修订，采用结构化评审协议 |

章节中的补充实现、离线固定回复和真实模型输出会分别标注。教材例题的使用会注明来源，固定回复不会描述为上游模型或本项目的真实 API 结果。

## Microsoft：先说明学什么，再解释怎样判断

实际参考：[AI Agents for Beginners 仓库](https://github.com/microsoft/ai-agents-for-beginners) 与 [Planning Design 章节](https://github.com/microsoft/ai-agents-for-beginners/blob/main/07-planning-design/README.md)。Planning Design 先交代本节范围与学习目标，再从总体目标、任务拆分走向结构化输出及代码；图示放在相应概念附近。

本项目借鉴其**可检查的学习目标与就近图解**：开篇说清读者需要掌握什么，代码前交代要解决的问题，图后解释应沿哪些箭头阅读。第六章据此补充输入字段对照与调用次序，第七章补充草稿版本与评审关系。我们没有移植它的服务配置、旅行任务实现或多 Agent 编排代码。

## Hugging Face：从熟悉的例子走向完整过程

实际参考：[Agents Course 课程介绍](https://huggingface.co/learn/agents-course/unit0/introduction) 与 [Thought–Action–Observation 循环讲解](https://huggingface.co/learn/agents-course/unit1/agent-steps-and-structure)。课程介绍明确先修知识，将基础学习、动手与应用任务分开；循环章节先回顾已有概念，再使用天气案例逐步说明各阶段，课程导航中配有小测验。

本项目借鉴其**先修提示、贯穿示例与阶段自查**：先接住读者已学过的上下文问题，围绕同一个例子解释请求、状态和结果，再让读者预测预算或修改条件。参考答案说明原因，不要求读者必须先配置环境才能读懂章节。课程的角色插画、截图、认证和排行榜没有移入本项目。

## 图示与结果的使用规则

本项目图示根据自己的代码和课程问题重新绘制，采用读者选择的白底、细线与少量配色。参考的是“概念旁边放对应图”“用箭头呈现先后与回路”等信息组织方法；未下载、描摹或翻译重绘上述项目的图片。

每幅图应回答一个明确问题，例如“下一次请求从哪里得到历史”“修订完成为何仍要评审”。模型、程序和工具的职责应能从节点及连接读出，调用预算和停止出口应与代码一致。颜色只辅助分组，关键含义还要用文字和箭头表达。图源与维护方式见 [图示规范](assets/README.md)。

结果采用两类证据：**真实 API 记录**展示一次实际模型行为，保留模型、日期、参数与结果；**固定回复演示和离线测试**验证流程、分支与输入传递。一次真实成功不等于总体质量已评估，固定回复通过也不等于模型具备同等能力。

阅读者应能在每章顺序找到：要解决的问题、核心机制、关键代码、实际结果、逐步解释、边界条件和带参考解析的练习。运行命令与完整源码用于复现这条学习过程。
