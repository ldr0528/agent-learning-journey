# 迁移练习 · 用资料制定计划与修订结论

[课程地图](../course-map.md) · [计划执行](../learning/planning.md) · [评审修订](../learning/reflection.md) · [RAG](../learning/rag.md) · [评估](../learning/evaluation.md)

读完第 06–09 章后，可以用这两道题检查：换掉销量和天气例子，是否仍能组织依赖、识别资料缺口、提出具体反馈，并核对结论。

两题都可以手工完成。下文的场景、练习稿和参考解析是题目内容，不是模型运行输出。第 6 章的执行器尚未自动接入研究资料检索，本页不要求把这些步骤交给现有入口执行。

## 共用资料

以下摘录来自本项目 [corpus.json](../../src/agent_learning/data/corpus.json)。D 系列编号对应文档；这里直接引用文档编号，不使用随分块设置变化的块编号。资料是依据 Hello-Agents 整理的教学摘要，不是教材原文。

**[D06] BM25 字面检索**

> BM25 按查询词在资料中的出现情况排序。较少见的词通常带来更高区分度，词频增大时贡献逐渐饱和，长度归一化避免长文档仅凭字数占优。本项目中文采用相邻双字分词，英文按词；它能匹配字面重合，但不具备训练得到的语义理解能力。

**[D07] Embedding 与向量检索**

> Embedding 模型将文本编码成稠密向量，通过向量距离寻找表达不同但含义相近的资料。索引文档与查询必须使用兼容的同一嵌入空间；更换模型通常需要重新编码知识库。向量相似度并非答案正确概率，也不能替代来源核对。当前项目的 BM25 基线没有调用嵌入模型。

**[D08] RAG 的来源与引用**

> RAG 的每个资料块应保留文档编号、标题、出处与正文。生成时仅能引用实际纳入上下文的证据，最终链接由程序从资料记录读取。引用编号合法只表示它来自这次证据，不保证资料真的支持每一句结论。报告应同时展示依据与仍缺少的信息，便于读者核查。

**[D10] 混合检索与重排序**

> 关键词检索擅长名称和精确术语，稠密向量检索能补充语义相近的表达。混合检索可以合并两路候选，再去重或重排序。查询改写可能增加召回，也可能偏离原问题；需要用相同评估题对照，不能只展示一个命中的例子。本项目只实现 BM25，其他策略作为可替换的后续方案。

**[D11] 检索评估与答案评估分开**

> 检索评估关注相关资料是否被找到以及排在什么位置；答案评估关注事实是否正确、引用是否支持结论、问题是否得到解决。程序测试能够验证消息回传、停止条件和解析规则，不能证明真实模型的回答质量。比较版本时应固定题目、知识库和参数，并记录结果来源。

**[D12] Recall MRR 与引用检查**

> 本项目的检索开发集为每个有答案问题标注相关文档。Recall@k 是前 k 个结果覆盖的相关文档数除以相关文档总数；MRR@k 是首个相关结果名次倒数的平均值，未命中记零。引用合法率和逐条结论引用覆盖率只检查引用结构；语义支持仍需人工评分。无答案题单独统计空结果比例。

D06、D07、D08、D10 的教材出处为 [Hello-Agents 第八章 §8.3](https://github.com/datawhalechina/hello-agents/blob/main/docs/chapter8/第八章%20记忆与检索.md)。D11、D12 对应 [第十二章 §12.1](https://github.com/datawhalechina/hello-agents/blob/main/docs/chapter12/第十二章%20智能体性能评估.md)，其中 D12 的指标定义是本项目的教学扩展。

## 练习一：先决定要查清什么，再决定检索方案

### 题目

某个团队正在设计内部手册问答助手。题设给定：资料包含产品名称、术语和流程说明；用户既会输入精确术语，也会换一种说法提问。团队已有 BM25 原型，但还没有两种检索方案在这批资料上的对照结果。

团队问：**是否应该直接用向量检索替换 BM25？** 你现在只有上面的六份资料。

请先做研究计划，再写出目前能够给出的答复。不要把“设计一个对照实验”写成“实验已经完成”，也不要根据检索原理直接编出哪种方案的分数更高。

### 需要交出的内容

1. **一张不超过四步的计划表。** 每步写明子问题、需要的资料或输入、依赖哪些前序结果，以及本步应交出什么。最后一步应回应团队的问题。
2. **一份结论与缺口表。** 至少列出两条能由资料支持的判断，以及两项做出替换决定前仍需取得的信息；区分资料事实、题设事实和你的建议。
3. **两种停止说明。** 一种是已经读完资料但不足以决定替换；另一种是假设四步计划交给第 6 章的执行器、总调用上限只有 4 时，程序会停在哪里。

### 核查表

| 检查项 | 可接受的表现 |
| --- | --- |
| 目标覆盖 | 最后回应“是否直接替换”，没有只介绍两个名词 |
| 依赖关系 | 比较与建议使用前面整理出的需求、原理和证据缺口 |
| 证据范围 | 同时使用 D06、D07；涉及对照与质量判断时使用 D10、D11 或 D12 |
| 不确定性 | 没有把语义匹配能力写成对所有问题都更好，也没有虚构分数 |
| 可执行的下一步 | 说明要补什么材料、如何比较，以及用什么标准检查 |
| 停止判断 | 区分研究答复中的“暂不能决定”和执行器的 `call_limit` |

<details>
<summary>参考解析：一种四步计划及其停止条件</summary>

| 步骤 | 子问题 | 输入与依赖 | 本步产物 |
| --- | --- | --- | --- |
| 1 | 这个项目需要回答哪些类型的问题？ | 题设；D10 提供精确术语与语义表达的区分 | 两类查询需求，以及尚待团队确认的要求 |
| 2 | 两条路线各能处理什么，变更需要注意什么？ | 第 1 步的需求；D06、D07、D10 | 字面匹配与语义匹配的对照；嵌入空间及重新编码要求 |
| 3 | 还缺哪些证据，怎样公平比较？ | 前两步；D11、D12 | 在相同问题与语料上比较的方案；检索与答案分开检查 |
| 4 | 现在能作何判断，何时再决定？ | 前三步的结果 | 有依据的初步建议、缺口和下一步 |

这不是唯一的排序。整理需求与阅读原理可以部分并行，但最后的建议必须用到它们的结果；不能先决定替换，再选择只支持这个决定的资料。

结论与缺口可以这样分开：

| 类型 | 内容 | 依据 |
| --- | --- | --- |
| 资料事实 | BM25 按词项出现情况匹配；向量检索可寻找表达不同但含义相近的内容 | D06、D07 |
| 资料事实 | 文档与查询需要兼容的嵌入空间，更换模型通常需要重新编码知识库 | D07 |
| 题设事实 | 这个项目同时有术语查询和换一种说法的查询，尚无方案对照结果 | 题目给定 |
| 仍缺的信息 | 两类查询的代表题，以及每题所需的相关资料标注 | 需要团队整理，六份资料没有提供 |
| 仍缺的信息 | 两种方案在该项目题目上的检索结果和回答质量 | 需要实际比较，不能从原理推算 |
| 初步建议 | 保留 BM25 作为比较基线，将向量或混合路线列为待验证方案 | 根据 D10、D11 和题设作出的建议，不是已证明的最优选择 |

对照方案至少要说明：固定题目、语料与分块等共同条件，记录各路线的配置；在相同 `k` 下检查相关资料覆盖与排名，再逐条核对答案和引用。题目应覆盖术语查询、不同表述，以及资料不能回答的情况。添加向量路线会改变检索方法，不能同时随意换掉题目与语料后再把全部差异归因于算法。

目前可以结束这次资料阅读，并给出有边界的答复：**现有资料支持比较两条路线，但不足以证明应该直接替换。应取得该项目的对照结果后，再作选择。** 停止阅读不等于已经完成最终选型。

调用预算是另一件事。假设有四个执行步骤，第 6 章的执行器还需要一次规划请求，共需五次调用。上限为 4 时，规划消耗一次，前三步执行再消耗三次；第四步开始前返回 `call_limit`，历史保留三条执行结果，`answer=None`。这只是对执行器计数规则的推演，不表示当前执行器已经能自动检索这些资料。

</details>

## 练习二：引用编号存在，结论仍可能越界

### 题目

继续使用同一团队的场景。下面是一份待评审的练习稿，其中故意混入了超出资料的结论：

> 向量检索能处理不同说法，因此这个项目应该立即替换 BM25；更换嵌入模型后，旧文档向量可以直接继续使用。[D07]
>
> 我们已经取得 Recall@3=100%，说明生成的回答全部正确。[D12]
>
> 只要每条结论都附上资料编号，就能保证来源支持结论。[D08]

请完成一次“评审 → 修订 → 复核”。修订稿需满足以下约束：

- 写成 **三条编号结论，加一条“资料缺口”说明**。
- 不超过 **220 个非空白字符**：汉字、英文字母、数字、标点、编号和引用都计入，空格与换行不计入。
- 只使用本页给出的资料。每条结论附上实际支持其内容的 D 系列编号，不补造实验结果。
- 保留“向量检索可以补充不同表述”等有效信息；删除或缩小没有依据的推断。

### 需要交出的内容

1. **评审表：** 逐项写出原句的问题、对应证据、具体修改建议。不能只写“回答不够好”。
2. **修订稿：** 满足上述结构、长度和引用要求。
3. **复核表：** 检查最新稿，而不是重看旧稿；分别检查内容、证据与格式，并注明还缺什么信息。

### 核查表

| 检查项 | 可接受的表现 |
| --- | --- |
| 发现问题 | 找到未经比较就决定替换、忽略嵌入空间、虚构分数、混淆检索与答案质量、把编号合法等同于语义支持 |
| 反馈可操作 | 指出具体句子，说明哪里越界，并写明如何保留或修改 |
| 修订保留有效信息 | 仍解释两条路线的差别，没有把全部内容删成“资料不足” |
| 来源支持 | 逐条对照资料文字，引用同时覆盖该条结论中的主要事实 |
| 约束检查 | 三条编号结论加一条缺口；按规定口径计数不超过 220 |
| 版本与结论 | 验收针对修订稿；没有把本次改写通过说成检索方案已经胜出 |

<details>
<summary>参考解析：从具体反馈到可核查的修订</summary>

可以把复合句拆开评审：

| 原稿中的问题 | 依据与原因 | 修改建议 |
| --- | --- | --- |
| “应该立即替换 BM25” | D07 说明向量检索的机制；D10、D11 要求对照，题设没有提供该项目的比较结果 | 保留语义匹配的用途，将立即替换改为待对照判断 |
| “旧文档向量可以直接继续使用” | D07 要求兼容的嵌入空间，并说明换模型通常需要重新编码 | 补上兼容条件与重新编码要求，不作无条件复用承诺 |
| “已经取得 Recall@3=100%” | 材料没有这次项目评估结果；D12 给的是指标定义 | 删除这个虚构的成绩，明确缺少对照结果 |
| “生成的回答全部正确” | D11、D12 区分检索覆盖与答案质量 | 说明 Recall 检查相关资料覆盖，回答还需单独核对 |
| “附编号就能保证支持结论” | D08 明确说明编号合法不保证语义支持 | 改为逐条核对资料是否支持主张 |

一份满足约束的修订稿如下：

```text
1. BM25 适合字面匹配，向量检索可补充语义相近的表达；是否替换应做同题、同语料对照。[D06][D07][D10][D11]
2. 更换嵌入模型通常需要重新编码知识库，文档与查询必须使用兼容的嵌入空间。[D07]
3. Recall@k 反映相关资料覆盖，不代表答案正确；引用编号合法也不保证结论得到支持。[D08][D11][D12]
资料缺口：材料未提供该项目的对照结果，还需比较检索表现并逐条核对回答。
```

按题目口径，这份稿子为 199 个非空白字符。复核时仍需看内容，不能因为字数合格就结束：

| 核查对象 | 复核结果 |
| --- | --- |
| 第 1 条 | D06、D07 支持匹配方式，D10、D11 支持对照要求；没有宣称向量已经胜出 |
| 第 2 条 | 保留 D07 的“通常”和兼容空间条件，没有扩大成无条件结论 |
| 第 3 条 | D11、D12 支持指标范围，D08 支持引用边界 |
| 资料缺口 | 指出题目没有提供的项目结果，没有为信息缺失虚造一个来源 |
| 结构与长度 | 三条编号结论加一条缺口，199 个非空白字符，满足 220 的上限 |

这份修订稿可以按本题标准通过，表示它准确表达了现有资料的结论与边界。它没有证明任何检索方案更优，也没有替团队完成尚缺数据的选型。

如果把同样过程交给第 7 章的循环，应把原任务、练习稿和具体反馈交给修订器；再次评审时使用最新修订稿及原任务。对旧稿的结论不能直接用于验收新稿。

</details>

## 怎样判断自己完成到了哪一步

| 层次 | 可观察的成果 |
| --- | --- |
| 理解机制 | 能说明计划、前序结果、评审反馈、引用和检索指标各自的作用 |
| 迁移运用 | 能针对本题交出完整计划与依赖、资料缺口、具体反馈、修订稿和复核表 |
| 进一步实践 | 能在新问题与资料上重复这套过程，并解释失败发生在计划、证据、表达还是约束检查 |

先独立完成题目，再展开参考解析。计划顺序和改写措辞可以不同；只要目标、依赖、证据和验收能互相对应，就不必复刻参考答案。
