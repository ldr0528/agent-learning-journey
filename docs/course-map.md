# 课程地图与阶段验收

[手册目录](../README.md#章节目录) · [教材映射](roadmap.md) · [配套入口](../examples/README.md)

每章按一个具体问题展开。先读原理与结果，再阅读对应函数，最后改变一个条件做实验。阅读阶段要求解释信息流；实践阶段要求留下可检查的轨迹、证据表或修改结果。

完成基础机制后，沿 [医疗险比较课程指南](insurance/course-guide.md) 把需求、工具、证据、预算、框架与协议用于同一业务。原有天气和课程问答仍用于拆解单个机制。

## 选择起点

| 你的基础与目标 | 建议路径 | 阶段产物 |
| --- | --- | --- |
| 能读 Python，还没有构建过 Agent | 从 01 开始，完成 A，再进入 05–07 | 一份标出每轮输入的消息轨迹 |
| 已用过工具调用，想理解状态与组织方式 | 先用 A 自查，再读 05–07，完成迁移练习 | 研究计划、依赖关系和修订对照 |
| 关注资料问答与质量 | 补齐 04–05，再读 08–09 | 带来源的回答、缺失说明和逐题评价 |
| 想把已有流程映射到框架或协议 | 能完成 A、C 后，再读 10–11 | 节点状态表与跨进程工具调用轨迹 |

只阅读时，可以利用正文中的代码和结果完成纸面分析。动手时再使用 [环境配置](getting-started.md) 与 [示例索引](../examples/README.md)。章节有先修关系，但不要求先安装所有可选库。

## 阶段验收

### A · 解释一次 Agent 运行

任务：依据 [第 03 章](learning/agent-loop.md) 北京、上海比较的三轮轨迹，填写“本轮输入—模型回复—程序执行—下一轮新增信息”四列表。再把上限设为 2，判断结束状态。

交付物是一张轨迹表和一句停止原因。逐项检查：

- 第一轮请求前没有天气结果；第二轮能看到北京结果；第三轮才同时看到两地结果。
- 原流程包含 3 次模型请求、2 次工具执行；Finish 是模型提出的结束操作。
- 上限为 2 时，程序已保存两地结果，但没有第三次模型请求生成比较结论。

能数出调用次数但无法指出结果进入哪次请求，说明仍需回到工具回传部分。

### B · 组织任务并限制执行

任务：完成 [迁移练习中的研究计划与报告修订](practice/transfer-exercises.md)。以给定资料为依据，为课程资料库选择检索方案；再评审一份存在过度结论的草稿。

交付物包括子问题与依赖表、证据缺口、逐条修改意见和修订后的报告。计划中的每一步要说明用到什么资料、产生什么结果；每处修订要能回到证据或任务约束。

验收时分别判断：计划是否覆盖目标，后一步是否得到前一步结果，评审意见是否可以执行，修订是否引入新错误。自动执行版本还应记录预算耗尽时留下的状态。现有规划、反思示例用于理解控制流程；这组练习先手工连接研究任务，不要求调用尚未实现的整合入口。

### C · 生成可追溯的研究回答

任务：按 [项目任务书](practice/research-agent.md) 检查三类问题：资料可以回答、主题命中但缺少所问事实、完全没有候选。可以先分析已有案例，再运行自己的问题。

交付物是一份逐题表：问题、检索候选、实际进入请求的证据、回答状态、每条结论的支持情况。另选一道没有出现在正文中的问题，先自行标注预期资料再检索，保留漏检和无法回答的结果。

验收要求：引用来自本次证据，资料不足时没有补写缺失事实，结论的限定范围与来源一致；检索分数与答案判断分别报告。开发题上的高分不作为新问题的通过证据。

### D · 用框架和协议组织执行

任务：沿 [源码调用链](practice/source-reading.md)，对照 LangGraph 三步问答图和 MCP 工具调用各完成一张表。

| 交付物 | 必须标明 | 核查依据 |
| --- | --- | --- |
| 节点状态表 | 节点读取的字段、写入的字段、下一条边；快照保存在哪里 | 图定义、运行轨迹和状态读取代码 |
| 工具通信表 | 工具定义、请求参数、服务端函数、回传消息 | 客户端会话、服务端注册和工具结果 |

能解释更换流程组织方式后，工具结果仍需回传给模型，才完成本阶段。三步问答图的内存快照与天气循环是独立实验；框架和协议的示例尚未组成完整研究工作流。此阶段不要求部署公网服务。

## 自查与参考答案

各章末尾包含练习或验收题，附参考解析。模型的措辞和计划条目可能不同，应按任务要求与证据判定。

结果不一致时，依次核对输入与参数、是否离线模式、工具结果、实际发送的消息、结束状态。只记录可复现差异，不先归因于模型能力。
