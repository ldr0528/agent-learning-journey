## 阶段验收

### A · 解释一次 Agent 运行

给出北京、上海比较的三轮轨迹，标注每次请求前模型已经拿到的信息。再把上限设为 2，解释为何终端有两个结果但任务仍未完成。回答必须区分程序状态、工具结果和下一次模型输入。

### B · 组织任务并限制执行

对同一个多步骤问题，画出逐轮决策、先规划执行、评审修订三种流程。标明谁产生计划或反馈、哪些结果被回传，以及预算不足时返回什么。代码能停下来，并不等于输出一定正确。

### C · 生成可追溯的研究回答

运行 [贯穿项目](practice/research-agent.md)，核对每条引用能否回到本次检索的资料；用固定题得到检索指标；对至少一条命中问题与一条资料不足问题人工核对。保存问题、模式和来源，不把固定演示混入真实模型统计。

### D · 用真实框架和协议复现机制

运行 LangGraph 示例，找到输入状态、节点与下一条边。运行 MCP 示例，确认初始化、工具发现、执行经过客户端与服务端会话；指出最后执行的本地函数。此阶段不要求部署公网服务。

## 自查与参考答案

各章末尾包含练习或验收题。基础章答案可折叠展开，后续章也给出应观察的行为。答案用于核对机制，真实模型的措辞和计划条目可能不同，应按内容与证据判定。

结果不一致时，依次核对输入与参数、是否离线模式、工具结果、实际发送的消息、结束状态。只记录可复现差异，不先归因于模型能力。

## 材料使用约定

教材转述保留定位；教学扩展说明新增或简化规则；示意用于解释结构；实测注明谁运行、是否用了真实模型或真实协议。来源许可见 [NOTICE](../NOTICE.md)，运行证据见 [证据登记](evidence.md)。
