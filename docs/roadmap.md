# 课程编排与教材映射

[手册目录](../README.md#章节目录) · [课程地图](course-map.md) · [实验说明](evidence.md)

本手册按概念与先修关系组织课程，从一次模型请求逐步推进到任务组织、资料检索和工具集成。

## 课程主线

```text
模型调用 → 工具回传 → 有限循环 → 检索与引用
                              ↓
上下文管理 → 规划执行 → 评审修订 → RAG 与评估
                              ↓
              LangGraph 流程表达 → MCP 工具通信
```

先理解请求、状态与停止条件，再引入任务组织和框架。天气是最小机制练习；本地资料问答是项目主线。当前规划、反思与框架/协议示例分别演示机制，研究任务的统一编排列在后续建设中。检索、生成和评估可以独立检查，便于定位问题来自哪一层。

## 学习节奏

建议按四个阶段推进，每个阶段完成相应练习后再进入下一部分。

| 阶段 | 章节 | 阶段成果 |
| --- | --- | --- |
| 基础机制 | 01–04 | 能说明一次带引用回答的完整消息流 |
| 上下文与组织 | 05–07 | 能解释三种组织方式的输入、预算与停止原因 |
| 检索与质量 | 08–09 | 能生成资料报告并区分检索错误与回答错误 |
| 框架与协议 | 10–11 | 能沿调用链定位节点与工具，并完成一次 MCP 调用 |

每章目标与验收见 [课程地图](course-map.md)。动手时遵循“理解机制 → 修改条件 → 运行 → 解释结果”的顺序。

## 范围与验收边界

第五章低代码平台实践跳过；第六章只选 LangGraph，不加入 AutoGen、AgentScope 或 CAMEL。多 Agent、A2A、ANP、模型训练和长期记忆不列为本轮任务。框架版与协议版服务于理解现有流程，不另建互不相干的产品路线。

课程成果以可阅读的正文、可运行的示例、可以解释的机制和带来源的资料回答为准。模型的成功率、成本和泛化能力需要采样评估；通过离线测试不替代这些证据。

## 后续建设与完成条件

当前已有基础循环、规划与反思的独立练习、本地 RAG、检索开发题，以及框架与协议示例。接下来的重点是让研究问题逐步变难，并将分散机制用于同一任务。以下四项是待实现的工作，不代表当前入口已经具备这些能力。

| 顺序 | 要解决的缺口 | 具体交付物 | 完成条件 |
| --- | --- | --- | --- |
| 1 · 资料与题目 | 14 篇短摘要难以呈现长文切分、跨来源和信息缺口 | 带章节定位和许可信息的较长课程材料；与开发题分开的验收题 | 题目覆盖单段回答、跨段比较、主题相关但无答案；先标注所需证据，再评价检索 |
| 2 · 研究任务 | 当前 RAG 一次检索、一次生成；规划和反思未接入 | 在同一资料任务上实现子问题、证据表、有限补查、草稿与修订 | 能沿子问题追溯证据；遗漏可被指出；预算耗尽保留部分成果并说明缺口 |
| 3 · 同题比较 | 还不能说明增加步骤是否值得 | 同一组题比较固定 RAG 与扩展研究流程，保留全部逐题结果 | 比较覆盖、证据支持、错误类型和调用成本；成功退出与答案正确分开判断 |
| 4 · 框架与协议 | 示例已建立连接，但尚未承载同一研究任务 | 用 LangGraph 表达已验证的研究流程；用 MCP 提供检索与片段读取工具 | 同一问题在迁移前后保持证据与停止语义；能处理工具失败与无效片段编号 |

第一项开始前，先用 [项目任务书](practice/research-agent.md) 明确目标和验收，再用 [迁移练习](practice/transfer-exercises.md) 手工验证计划与证据关系。增加文档、工具或模型请求都应对应一个已发现的问题；没有对照结果时，不预设流程越复杂效果越好。

这条建设路线仍以 Hello-Agents 第四、八、九、十二和十四章为知识来源。框架与协议按第六章 LangGraph 和第十章 MCP 的选定范围衔接，不扩展为多 Agent 课程。
