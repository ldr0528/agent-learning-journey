## 怎么读一份记录

Markdown 展示命令、终端输出和逐次模型原话。JSON 的 `calls` 数组记录对应输入与响应：

| 字段 | 可以核对什么 |
| --- | --- |
| `request.messages` | 模型究竟收到哪些问题、历史、工具结果和证据 |
| `request.tools` | MCP 工具定义如何映射给模型；只有原生工具样本有此字段 |
| `response.choices` | 原始回答、工具请求、结束原因 |
| `response.usage` | 服务商报告的输入、输出与总 token |
| `source_commit` / `source_dirty` | 运行前的仓库基准提交，以及当时源码是否还有改动 |
| `source_files_sha256` | 当时源码文件指纹，按LF规范化，补充说明未提交源码的版本 |

本轮在修改工作区中运行，`source_dirty=true`；`source_commit` 是基准，不能独自代表新增代码。请求、提示、实际证据、参数与源码指纹一并保留，后续阅读应结合本次发布的实现。记录不包含密钥、认证头或私人会话。

## 复现与补充自己的结果

先按 [环境说明](../getting-started.md) 配置模型，安装需要的可选依赖。想只运行而不保存输入，可复制每份记录的命令；想记录一个新的公开教学样本，可使用：

```bash
python scripts/record_live.py planning --output-dir outputs/my-live-run
```

该命令会实际请求模型；目标记录已存在时拒绝覆盖。其他案例名称见脚本的 `CASES`。默认写入被Git忽略的 `outputs/`；公开前应检查输入只含适合公开的教学内容，再将经过核对的记录放入新的日期目录。CI 只做无需模型API的检查，不自动调用真实模型。
